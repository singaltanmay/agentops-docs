# Consolidation — coding mixed gate

**Week 2 · Review · 60 min (light)** · Month 6 — Interview Phase

## Objective
Pass the Week 2 mixed gate: one production rep + one pattern-recognition set + one trace diagnosis, all timed, all unaided.

## Why this exists
The gate samples Week 2 the way a real screen does — mixed, timed, no warm-up lap — so its score is the honest readiness signal for Week 4's mocks.

## Prerequisites
Lessons 1–4 done.

## Retrieval warm-up (closed-book, 8–12 min)
1. **Previous lesson (Month 6 Week 2, Lesson 4 (Coding reps II — DSA refresh at senior-SWE level)):** state its objective and its verification in one sentence each — from memory, guide closed.
2. **Spaced review (Month 6 Week 1):** one generative item — write the key command, schema, or rule from that lesson without looking.
3. **Interleaved discrimination:** one item mixing this week's pattern with its most confusable neighbour, unlabelled — name which is which and why.
4. **Prediction:** predict the output/behaviour of today's first build step before you run it. Write the prediction down.
5. Tag every answer with a confidence (0–100%) *before* checking. A miss on a prerequisite for today changes today's plan now, per the opening routine.

## Prerequisite check
Re-run the previous lesson's independent verification (Month 6 Week 2, Lesson 4 (Coding reps II — DSA refresh at senior-SWE level)) before starting. If it no longer passes, repair first and compress today's objective — never stack new work on a broken base.

## Core concept
No new concept. Gate composition mirrors a 60-minute screen: 20 min production rep (new variant), 10 min recognition sprint (5 statements), 20 min trace diagnosis (new planted fault), 10 min self-scoring + gap log.

## Build steps
Expected output is stated *before* you run each step. If you see something else, stop, classify the error (slip / execution-model / API misconception / design misconception), and check the failure notes.

### Step 1 — Run the three parts
Per the composition; log times strictly.

**Expected output:** All three artefacts exist with times.

### Step 2 — Score + compare
Score against the week's rubrics; compare trace-diagnosis vs Lesson 3 (improvement is the point of reps).

**Expected output:** Comparison recorded; trend stated in one line per skill.

### Step 3 — Pay down one debt item
Oldest debt item repaired with evidence.

**Expected output:** Debt log shrinks by one.

### Step 4 — Spend check (time edition)
Month 6 runs on Azure budget ≈$174 for system upkeep — confirm the Workbench's demo posture is inside it (demo windows only).

**Expected output:** Cost posture noted; min-replica toggles (Month 3) are off outside demo windows.

## Independent verification (checkpoint)
A screen-shaped readiness score exists for all three coding skills, with a trend line for trace debugging.

## Unaided probe (closed-guide)
State your confidence (0–100%) before checking each answer.

1. Interleaved: given three fresh problem statements — pattern, production-flavour, or trace — classify and state your first move for each.
2. Teach-back: your debugging method + your weakest pattern + its repair plan — the honest 60-second version.

## Definition of done
