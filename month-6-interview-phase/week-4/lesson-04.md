# Targeted application wave — fit-first, evidence-attached

**Week 4 · Build · 75 min** · Month 6 — Interview Phase

## Objective
Execute the targeted application wave: the next-3 from Week 3's audit + any loop-driven additions, each application assembled fit-first (posting's named skills → your proving artefact, explicitly) — with the 5-question external-employer screen applied where the standing job-targeting rules require it.

## Why this exists
Volume is not the strategy; fit × evidence is. Each application is a small FDE exercise: read their problem (the posting), map your artefacts to it, and let the mapping — not a generic résumé blast — carry the application.

## Prerequisites
Week 3's claims-audited résumé + next-3 list; story bank v1+.

## Core concept
Per-application protocol: (1) extract the posting's named skills/requirements verbatim; (2) map each to a proving artefact (or mark the honest gap); (3) if ≥2 core requirements are honest gaps, deprioritise the application (note it, don't force it); (4) tailor the résumé's top section + cover note from the map (claims audit rules still bind — tailored ≠ inflated); (5) log in the pipeline tracker with tier + map link. Standing filter reminder (from the goal): agentic-AI roles only; the PERM 5-question screen gates external employers before interview agreement where it applies.

## Build steps
Expected output is stated *before* you run each step. If you see something else, stop, classify the error (slip / execution-model / API misconception / design misconception), and check the failure notes.

### Step 1 — Process application 1
Full protocol; map committed to the tracker.

**Expected output:** Application submitted; map shows ≥ core requirements artefact-backed.

### Step 2 — Process applications 2–3
Same protocol.

**Expected output:** Both submitted or deprioritised with the gap reason recorded (deprioritising is a valid protocol outcome).

### Step 3 — Refresh the pipeline view
All live applications by tier/stage in one view; next actions (follow-ups, prep per company) noted.

**Expected output:** Pipeline current; each active loop has its prep note (which archetypes/stories to weight).

### Step 4 — Wave retro
One paragraph: what the maps revealed about your evidence coverage across the market's asks.

**Expected output:** Retro committed; any systematic gap becomes a post-course backlog item, named.
