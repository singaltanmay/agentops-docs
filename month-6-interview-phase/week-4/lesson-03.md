# The repair sprint — close the final gap set

**Week 4 · Build · 75 min** · Month 6 — Interview Phase

## Objective
Execute the final repair set (≤4 items from gap list v2) as targeted reps — one per gap class present (knowledge: re-derive from the artefact; evidence: drill citation-on-demand; delivery: timed re-answers) — each verified by a fresh probe, not by the rep itself.

## Why this exists
Repairs follow the course's oldest rule: a gap is closed by an *unaided probe on new material*, never by re-performing the failed item. This sprint is mastery-gating applied to interview skills.

## Prerequisites
Gap list v2 frozen; repair set named.

## Retrieval warm-up (closed-book, 8–12 min)
1. **Previous lesson (Month 6 Week 4, Lesson 2 (Mock loop II — coding screen + behavioural, back-to-back)):** state its objective and its verification in one sentence each — from memory, guide closed.
2. **Spaced review (Month 6 Week 3):** one generative item — write the key command, schema, or rule from that lesson without looking.
3. **Interleaved discrimination:** one item mixing this week's pattern with its most confusable neighbour, unlabelled — name which is which and why.
4. **Prediction:** predict the output/behaviour of today's first build step before you run it. Write the prediction down.
5. Tag every answer with a confidence (0–100%) *before* checking. A miss on a prerequisite for today changes today's plan now, per the opening routine.

## Prerequisite check
Re-run the previous lesson's independent verification (Month 6 Week 4, Lesson 2 (Mock loop II — coding screen + behavioural, back-to-back)) before starting. If it no longer passes, repair first and compress today's objective — never stack new work on a broken base.

## Core concept
Per-gap protocol: state the gap + its class → the repair rep (new material, same skill) → the verification probe (a *second* new item) → verdict (closed / still open). Still-open gaps are not hidden: they go on the final readiness sheet (Lesson 5) with a compensating strength noted — interviewers find gaps anyway; arriving with them named is a senior signal.

## Build steps
Expected output is stated *before* you run each step. If you see something else, stop, classify the error (slip / execution-model / API misconception / design misconception), and check the failure notes.

### Step 1 — Repair gap 1–2
Protocol per gap, in ranked order.

**Expected output:** Verdicts recorded with probe artefacts.

### Step 2 — Repair gap 3–4 (if present)
Same protocol.

**Expected output:** Verdicts recorded.

### Step 3 — Update the bank/frame if a repair produced better material
Only evidence-backed improvements land; version-bump with a note (mock-evidence exception to the freezes, as designed).

**Expected output:** Any change is versioned + justified in one line.

### Step 4 — Readiness sheet draft
Start `interview/readiness.md`: strengths (with artefacts), open gaps (named + compensated), logistics status.

**Expected output:** Draft committed; it will be finalised in Lesson 5.

## Independent verification (checkpoint)
Every final-set gap has a verdict from a fresh probe; the readiness sheet exists in draft with honest open items.

## Unaided probe (closed-guide)
State your confidence (0–100%) before checking each answer.

1. Generative: the repair set's verdicts + the probe that decided each, unaided — then check.
2. Prediction: which open gap (if any) is most likely to be *found* in a real loop, and what's your in-room recovery line for it? (Write the line.)

## Definition of done
- [ ] All build steps completed with expected outputs matched
- [ ] Independent verification passed
- [ ] Unaided probe: majority correct *with explanations* (else this lesson's KCs are `fragile` — repair scheduled)
- [ ] System left running; checkpoint committed
- [ ] Log entry written (below) and PROGRESS.md updated

## Log entry prompt
Write your own 3 lines — *what I built / what broke and why / what I still can't do unaided* — then set this lesson's status in PROGRESS.md (`assisted` if any step was demonstrated for you, `mastered` only when the probe passed unaided).
