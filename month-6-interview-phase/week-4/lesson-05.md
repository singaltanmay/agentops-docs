# Consolidation — final readiness gate

**Week 4 · Review · 60 min (light)** · Month 6 — Interview Phase

## Objective
Pass the final readiness gate: one unseen item per loop component (mini-design, production rep, trace diagnosis, story with probe, discovery segment) — and finalise the readiness sheet.

## Why this exists
The course's last mastery gate, shaped exactly like the thing it certifies. Passing it doesn't guarantee offers (nothing here can) — it certifies that your preparation is evidence-complete, which is the part you control.

## Prerequisites
Lessons 1–4 done; readiness sheet in draft.

## Retrieval warm-up (closed-book, 8–12 min)
1. **Previous lesson (Month 6 Week 4, Lesson 4 (Targeted application wave — fit-first, evidence-attached)):** state its objective and its verification in one sentence each — from memory, guide closed.
2. **Spaced review (Month 6 Week 3):** one generative item — write the key command, schema, or rule from that lesson without looking.
3. **Interleaved discrimination:** one item mixing this week's pattern with its most confusable neighbour, unlabelled — name which is which and why.
4. **Prediction:** predict the output/behaviour of today's first build step before you run it. Write the prediction down.
5. Tag every answer with a confidence (0–100%) *before* checking. A miss on a prerequisite for today changes today's plan now, per the opening routine.

## Prerequisite check
Re-run the previous lesson's independent verification (Month 6 Week 4, Lesson 4 (Targeted application wave — fit-first, evidence-attached)) before starting. If it no longer passes, repair first and compress today's objective — never stack new work on a broken base.

## Core concept
Gate standard: each component scored against its standing rubric; the sheet records per-component status (ready / ready-with-known-gap) — a component is never marked plain 'ready' against a known open gap from Lesson 3. The sheet also carries: logistics (demo, links, kit), the negotiation prep pointer (Lesson 6), and the post-course backlog (from Lesson 4's retro).

## Build steps
Expected output is stated *before* you run each step. If you see something else, stop, classify the error (slip / execution-model / API misconception / design misconception), and check the failure notes.

### Step 1 — Run the five gate items
Unseen draws, timed, scored per standing rubrics.

**Expected output:** Five scores recorded with artefacts.

### Step 2 — Finalise the readiness sheet
Per-component status + open gaps + compensations + logistics checklist complete.

**Expected output:** Sheet finalised and committed; it contains no claim the gate didn't test.

### Step 3 — Pay down one debt item
The course's oldest remaining debt item, repaired with evidence — or formally written off with a reason (write-offs are allowed exactly once, here, in writing).

**Expected output:** Debt log reaches its final state; every entry is closed or written off with a reason.

### Step 4 — Course-level spend + systems check
Confirm the Workbench demo posture fits the ≈$174 Month 6 column for the loop season; crons/automations that should pause during loops are listed.

**Expected output:** Posture noted; the system stays demo-ready without babysitting.

## Independent verification (checkpoint)
The readiness sheet is final and gate-backed; the debt log is closed out honestly; Month 6's last build has a verified launchpad.

## Unaided probe (closed-guide)
State your confidence (0–100%) before checking each answer.

1. Interleaved: five rapid draws — one per component — name your first move for each in one line.
2. Teach-back: your readiness, stated as the sheet states it (strengths + named gaps) — the honest version, delivered plainly.

## Definition of done
- [ ] All build steps completed with expected outputs matched
- [ ] Independent verification passed
- [ ] Unaided probe: majority correct *with explanations* (else this lesson's KCs are `fragile` — repair scheduled)
- [ ] System left running; checkpoint committed
- [ ] Log entry written (below) and PROGRESS.md updated

## Log entry prompt
Write your own 3 lines — *what I built / what broke and why / what I still can't do unaided* — then set this lesson's status in PROGRESS.md (`assisted` if any step was demonstrated for you, `mastered` only when the probe passed unaided).
