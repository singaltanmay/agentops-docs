# FDE drill II — ambiguous brief → shipped plan in 90 minutes

**Week 3 · Build · 75 min** · Month 6 — Interview Phase

## Objective
Run the timed FDE build-plan exercise: from a fresh ambiguous brief, produce in 90 minutes a scoped plan (architecture sketch, eval plan, security posture, week-by-week delivery, risks) + a 5-minute pitch of it — scored against the FDE rubric.

## Why this exists
This is the FDE loop's signature exercise (brief → plan under time pressure). Your plan template is the course itself, compressed: Month 5's engagement is the reference implementation — the drill checks you can *re-derive* it for a new brief, fast.

## Prerequisites
Lesson 2's discovery artefact + its under-explored area as the emphasis. Session runs 90 minutes of plan work + pitch (schedule the deep-build slot if needed — the 75-min label is the lesson's core; the plan clock is 90 by the exercise's definition).

## Retrieval warm-up (closed-book, 8–12 min)
1. **Previous lesson (Month 6 Week 3, Lesson 2 (FDE drill I — customer discovery role-play)):** state its objective and its verification in one sentence each — from memory, guide closed.
2. **Spaced review (Month 6 Week 2):** one generative item — write the key command, schema, or rule from that lesson without looking.
3. **Interleaved discrimination:** one item mixing this week's pattern with its most confusable neighbour, unlabelled — name which is which and why.
4. **Prediction:** predict the output/behaviour of today's first build step before you run it. Write the prediction down.
5. Tag every answer with a confidence (0–100%) *before* checking. A miss on a prerequisite for today changes today's plan now, per the opening routine.

## Prerequisite check
Re-run the previous lesson's independent verification (Month 6 Week 3, Lesson 2 (FDE drill I — customer discovery role-play)) before starting. If it no longer passes, repair first and compress today's objective — never stack new work on a broken base.

## Core concept
Plan rubric (write it before starting): scope discipline (smallest valuable deployment named; non-goals explicit), architecture (fits the brief's constraints; Month 1–3 patterns reused *by name*), eval plan (golden set before tuning; judges calibrated; gates), security (trifecta checked; permissions at retrieval), delivery realism (weeks map to the course's actual cadence), risk honesty (top 3 risks with mitigations, one of them 'the data is worse than stated').

## Build steps
Expected output is stated *before* you run each step. If you see something else, stop, classify the error (slip / execution-model / API misconception / design misconception), and check the failure notes.

### Step 1 — Read + clarify (10 min of the 90)
Extract constraints; list the 5 clarifying questions you'd ask (you get answers to 2 — choose).

**Expected output:** Constraint list + chosen questions recorded (the choice is scored).

### Step 2 — Draft the plan (65 min)
Per the rubric's sections; architecture sketch included; numbers estimated with assumptions stated.

**Expected output:** Plan artefact complete inside the clock.

### Step 3 — Pitch (5 min) + Q&A defence (10 min)
Present; defend two hostile questions (cost challenge + 'why not just use ChatGPT?' class).

**Expected output:** Pitch delivered; defences drew on your measured artefacts (note where they didn't).

### Step 4 — Score + retro
Rubric score; the weakest section named; one repair rep scheduled in Week 4 if the loop is near.

**Expected output:** Score + retro committed.

## Independent verification (checkpoint)
A scored, timed brief-to-plan artefact + pitch record exist; the plan's sections are rubric-complete.

## Unaided probe (closed-guide)
State your confidence (0–100%) before checking each answer.

1. Generative: the plan rubric's six sections, unaided.
2. Teach-back: your pitch's opening 60 seconds — does it lead with the customer's outcome or your technology? (Rewrite if the latter.)
