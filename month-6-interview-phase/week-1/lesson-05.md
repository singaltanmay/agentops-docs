# Consolidation — design-drill mixed gate + frame card freeze

**Week 1 · Review · 60 min (light)** · Month 6 — Interview Phase

## Objective
Pass the Week 1 mixed gate: two rapid-fire mini-designs (15 min each) scored on the frame, and freeze the frame card for the month.

## Why this exists
The frame must survive compression (panel interviews, screens) — 15-minute reps prove it isn't a 45-minute crutch.

## Prerequisites
Lessons 1–4 done.

## Retrieval warm-up (closed-book, 8–12 min)
1. **Previous lesson (Month 6 Week 1, Lesson 4 (Write-up 2 — the evals + judge-calibration story, published)):** state its objective and its verification in one sentence each — from memory, guide closed.
2. **Spaced review (Month 5 (capstone evidence)):** one generative item — write the key command, schema, or rule from that lesson without looking.
3. **Interleaved discrimination:** one item mixing this week's pattern with its most confusable neighbour, unlabelled — name which is which and why.
4. **Prediction:** predict the output/behaviour of today's first build step before you run it. Write the prediction down.
5. Tag every answer with a confidence (0–100%) *before* checking. A miss on a prerequisite for today changes today's plan now, per the opening routine.

## Prerequisite check
Re-run the previous lesson's independent verification (Month 6 Week 1, Lesson 4 (Write-up 2 — the evals + judge-calibration story, published)) before starting. If it no longer passes, repair first and compress today's objective — never stack new work on a broken base.

## Core concept
Mini-design format: prompt → 3 min clarify/sketch aloud → 12 min lenses in order, spoken or written; score = lenses covered with at least one number each. Prompts: (a) doc-QA over a regulated corpus (permissions lens heavy); (b) an agent that files support tickets (gate/trifecta heavy).

## Build steps
Expected output is stated *before* you run each step. If you see something else, stop, classify the error (slip / execution-model / API misconception / design misconception), and check the failure notes.

### Step 1 — Mini-design A (doc-QA, regulated)
15 minutes, scored live against the frame.

**Expected output:** Score recorded; permissions design used retrieval-time trimming (Month 5) unprompted — or it's a repair item.

### Step 2 — Mini-design B (ticket-filing agent)
15 minutes, scored.

**Expected output:** Score recorded; the approval gate appears without prompting — or repair item.

### Step 3 — Freeze the frame card
Card reaches `interview-frame-v1`; further changes only from mock-loop evidence (Week 4).

**Expected output:** Frozen version tagged in the interview folder.

### Step 4 — Pay down one debt item
Oldest debt item repaired with evidence.

**Expected output:** Debt log shrinks by one.

## Independent verification (checkpoint)
Two scored mini-designs exist; the frame is frozen; automaticity gaps (trimming, gates) are either demonstrated or scheduled for repair.

## Unaided probe (closed-guide)
State your confidence (0–100%) before checking each answer.

1. Interleaved: three design prompts — for each, name the heaviest lens and the first clarification question.
2. Teach-back: the frame, delivered as if teaching it to another candidate — 3 minutes. (Teaching it is the mastery probe.)

## Definition of done
- [ ] All build steps completed with expected outputs matched
- [ ] Independent verification passed
- [ ] Unaided probe: majority correct *with explanations* (else this lesson's KCs are `fragile` — repair scheduled)
- [ ] System left running; checkpoint committed
- [ ] Log entry written (below) and PROGRESS.md updated

## Log entry prompt
Write your own 3 lines — *what I built / what broke and why / what I still can't do unaided* — then set this lesson's status in PROGRESS.md (`assisted` if any step was demonstrated for you, `mastered` only when the probe passed unaided).
